# CU02 · Gestionar pacientes

| | |
|---|---|
| RF | RF12 |
| Actor | Administrativo (el Médico solo consulta) |
| Fase / iteración | Elaboración · It2 |
| Módulo | servidor 1.1.0 (paquete `pacientes`) |
| Rama | `feature/CU02-servidor` |

## Flujo principal
1. El administrativo introduce DNI, nombre, apellidos, fecha de nacimiento, teléfono y correo (opcional).
2. El sistema valida los datos y que el DNI no esté repetido, y asigna un id `PAC-n`.
3. El administrativo puede modificar los datos (salvo el DNI), consultar, buscar por DNI y dar de baja.

## Flujos alternativos
- 2a. DNI con formato o letra incorrectos, teléfono o correo inválidos, fecha fuera de rango → `IllegalArgumentException`.
- 2b. DNI ya registrado → `ReglaNegocioException`.
- 3a. Modificar el DNI, modificar un paciente de baja o dar de baja dos veces → `ReglaNegocioException`.
- La baja es **lógica**: el paciente se conserva para su historial.

## Contratos
- `api.ApiPacientes` (permisos `GESTIONAR_PACIENTES`, `CONSULTAR_PACIENTES`).
- `pacientes.ServicioPacientes` (lo usan otros componentes: `obtenerActivo`).

## Diseño de pruebas
| Entrada | CEV | CEI | Valores límite / conjetura de errores |
|---|---|---|---|
| DNI | 8 dígitos + letra correcta (también en minúsculas o con espacios) | 7 o 9 dígitos; sin letra; letra incorrecta; Ñ; nulo; vacío | 00000000T, 99999999R |
| Fecha de nacimiento | [01/01/1900, hoy] | anterior a 1900; posterior a hoy; nula | 31/12/1899, 01/01/1900, hoy, mañana |
| Teléfono | 9 dígitos empezando por 6, 7, 8 o 9 | prefijo 5; 8 o 10 dígitos; letras; vacío | — |
| Correo | vacío/nulo (opcional); `a@b.c` | sin @ | — |
| Operación | alta, modificar, baja, consultar | DNI repetido; modificar DNI; baja doble; id inexistente | un alta fallida no consume id |
| Rol | Administrativo (todo), Médico (consulta) | Paciente, Administrador | — |
