## Flujo principal
1. El médico indica paciente, tipo de prueba, indicación clínica, justificación y prioridad
   (urgente, preferente, ordinario).
2. El sistema comprueba que el paciente está activo y que el tipo existe en el catálogo.
3. Se crea la solicitud en estado SOLICITADA con la fecha actual y el médico como solicitante; queda en
   la lista de espera para que admisión la cite (CU06).

## Flujos alternativos
- 2a. Paciente inexistente o de baja → `ReglaNegocioException`; tipo inexistente → `NoEncontradoException`.
- 2b. El paciente ya tiene una solicitud **abierta** (SOLICITADA o CITADA) del mismo tipo → `ReglaNegocioException`.
- 4. El médico solicitante puede cancelar la solicitud mientras no esté citada (otro médico → `AccesoDenegadoException`).

## Contratos
- `api.ApiSolicitudes` (permisos `SOLICITAR_PRUEBAS`, `CONSULTAR_SOLICITUDES`, ambos de datos clínicos).
- `solicitudes.ServicioSolicitudes`. `SolicitudPrueba` sustituye a la clase de prueba inicial del paquete raíz.
