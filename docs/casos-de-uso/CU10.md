# CU10 · Prescribir seguimiento

| | |
|---|---|
| RF | RF07 |
| Actores | Médico; Temporizador (tarea programada, la lanza el Administrador) |
| Fase / iteración | Construcción · It9 (con CU16, D-016) |
| Módulo | servidor 1.8.0 (paquete `seguimiento`) |
| Rama | `feature/It09-seguimiento-servidor` |

## Flujo principal
1. El médico prescribe un seguimiento: paciente, tipo de prueba, indicación, justificación, prioridad,
   periodicidad (meses), número de revisiones y fecha de la primera revisión.
2. El sistema comprueba que el paciente está activo y que el tipo de prueba admite seguimiento; el paciente
   recibe un aviso SEGUIMIENTO (CU12).
3. El temporizador genera las revisiones vencidas: por cada seguimiento ACTIVO cuya próxima revisión es
   hoy o anterior se crea una solicitud SOLICITADA (CU04) vinculada al seguimiento, que entra en la lista de
   espera, y se avisa al paciente. La siguiente revisión se fija a `primera + periodicidad × generadas`.
4. Al generar la última revisión el seguimiento pasa a FINALIZADO.

## Flujos alternativos
- Tipo de prueba sin seguimiento, paciente de baja o inexistente, primera revisión anterior a hoy →
  `ReglaNegocioException`; tipo inexistente → `NoEncontradoException`.
- La revisión anterior sigue abierta (solicitud SOLICITADA o CITADA del mismo tipo) → la nueva revisión se
  **aplaza** a la siguiente ejecución del temporizador (no se duplica la solicitud).
- Cancelar: solo el médico que lo prescribió (`AccesoDenegadoException`) y solo si está ACTIVO
  (`ReglaNegocioException`). Las solicitudes ya generadas no se cancelan.

## Contratos
- `seguimiento.ServicioSeguimiento` (interno); usa `ServicioSolicitudes.solicitarSeguimiento` y `Notificador`.
- `api.ApiSeguimiento` (permisos `PRESCRIBIR_SEGUIMIENTOS` y `EJECUTAR_TAREAS_PROGRAMADAS`).

## Diseño de pruebas
| Entrada | CEV | CEI | Valores límite / conjetura de errores |
|---|---|---|---|
| Periodicidad (meses) | [1, 60] | ≤ 0; > 60 | −1, 0, 1, 60, 61 |
| Nº de revisiones | [1, 20] | ≤ 0; > 20 | 0, 21 |
| Primera revisión | ≥ hoy | < hoy | ayer / hoy |
| Tipo de prueba | admite seguimiento | no lo admite; inexistente | — |
| Paciente | activo | inexistente | — |
| Momento del temporizador | ≥ próxima revisión | < próxima revisión | día anterior / mismo día; ejecutar dos veces |
| Revisión anterior | cerrada | abierta | se aplaza y se genera al cancelarla |
| Estado | ACTIVO | FINALIZADO, CANCELADO | no genera más revisiones; cancelar dos veces |
| Médico | el que prescribe | otro médico | — |
| Rol | Médico (prescribe); Administrador (temporizador) | Paciente, Administrativo | — |
